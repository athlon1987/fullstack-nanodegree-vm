# Next.js 16.4.6 engineering notes

Framework rules for this codebase: Next.js 16.4.6 (App Router), React 19.3, Tailwind CSS 4.3 through `@tailwindcss/turbopack`, TypeScript 5, with `cacheComponents: true` and `partialPrefetching: true`.

**Source of truth** is the docs bundled with the installed version. Paths in parentheses are relative to `node_modules/next/dist/docs/01-app/`, shortened: `gs/` = `01-getting-started/`, `guides/` = `02-guides/`, `api/` = `03-api-reference/`, and inside `api/`: `directives/` = `01-directives/`, `components/` = `02-components/`, `files/` = `03-file-conventions/`, `fn/` = `04-functions/`, `config/` = `05-config/01-next-config-js/`, `cli/` = `06-cli/`.

**[V]** = also verified empirically on 16.4.6 (`next build` + `next start`, plus `next dev` where stated) in a throwaway app outside this repo. Anything without [V] is from the docs and not empirically verified.

## 1. Version facts and what changed

- Node >= 20.9, TypeScript >= 5.1. Turbopack is the default for `next dev` and `next build` (gs/01-installation.md, guides/upgrading/version-16.md).
- `middleware.ts` is now **`proxy.ts`** exporting `proxy` (or a default export). Node.js runtime only; a `runtime` export in it throws (guides/upgrading/version-16.md, api/files/proxy.md).
- Request APIs are **async only**: `cookies()`, `headers()`, `draftMode()` and the `params` / `searchParams` props are Promises. So are `params`/`id` in `opengraph-image`, `icon`, `apple-icon` and `id` in `sitemap` (guides/upgrading/version-16.md).
- Global type helpers, no import: `PageProps<'/route'>`, `LayoutProps<'/route'>`, `RouteContext<'/route'>`. Generated by `next dev`, `next build` or `next typegen` into `.next/types` (dev: `.next/dev/types`). The literal must be a real route or type-checking fails [V] (gs/03-layouts-and-pages.md, api/cli/next.md).
- `next lint` is removed and `next build` no longer lints; run the `eslint` CLI with the flat config (gs/01-installation.md).
- Under Cache Components these exports are **build errors**: `dynamic`, `dynamicParams`, `revalidate`, `runtime` (even `'nodejs'`) [V for these four], and `fetchCache`; `experimental_ppr` is removed. New segment configs: `ensureStatic`, `instant`, `prefetch` (api/files/02-route-segment-config/index.md, guides/migrating-to-cache-components.md).
- Default caching: nothing is cached implicitly. `fetch` is uncached unless inside `"use cache"`; GET route handlers run per request unless they can be prerendered (guides/migrating-to-cache-components.md).
- `revalidateTag(tag, profile)` needs the second argument; `updateTag` (Server Functions only) and `refresh` are new; `cacheLife` / `cacheTag` lost the `unstable_` prefix (guides/upgrading/version-16.md).
- `error.tsx` receives `{ error: unknown, retry }`; prefer `retry()` over the older `reset()` (api/files/error.md). Every parallel-route slot needs a `default.tsx` or the build fails (guides/upgrading/version-16.md).
- `next/image`: `priority` is deprecated (use `preload`), `images.qualities` defaults to `[75]`, `images.domains` is deprecated (use `remotePatterns`) (guides/upgrading/version-16.md).
- Navigation keeps up to 3 previous routes mounted but hidden (React `<Activity>`): `useState`, form input and scroll survive leaving and returning (api/config/cacheComponents.md, guides/preserving-ui-state.md).
- Next.js no longer overrides `scroll-behavior: smooth` on navigation unless `<html>` has `data-scroll-behavior="smooth"`, and the scroll handler leaves focus unchanged (guides/upgrading/version-16.md).

## 2. Cache Components (`cacheComponents: true`)

**Model.** Every page is partially prerendered. At build time Next.js renders the tree; whatever completes becomes the **static shell** (HTML + RSC payload). Work that cannot complete must be handled explicitly or the build fails. Build output: `○` fully static, `◐` static shell plus streamed content, `ƒ` rendered on demand (gs/08-caching.md, guides/building.md).

| Kind of work | Result |
|---|---|
| Module imports, sync fs, pure computation (our typed content modules) | Prerendered automatically |
| `"use cache"` function or component | Cached and included in the shell |
| Runtime data inside `<Suspense>` or under `loading.tsx` | Fallback in the shell, content streams per request |
| Runtime data outside `<Suspense>` | **Build error** |

**Errors people hit, and the fix** (gs/08-caching.md, guides/building.md, guides/migrating-to-cache-components.md):

| Code | Outcome | Fix |
|---|---|---|
| `await params` at page top, route has **no** `generateStaticParams` | Build error `blocking-prerender-dynamic` [V] | Await inside `<Suspense>`, or add `loading.tsx`, or add `generateStaticParams` |
| `await params` at page top, route **has** `generateStaticParams` | Builds, listed params are `○` [V]; `next dev` reports `instant-shell-url-data` [V] | Await inside a `<Suspense>` child (clean in dev [V]) |
| `cookies()`, `headers()`, `searchParams` outside `<Suspense>` | Build error [V for `cookies()`] | Move into a Suspense-wrapped component |
| `new Date()`, `Date.now()`, `Math.random()`, `crypto.randomUUID()` in a Server Component | Build error [V]; `instant = false` does not clear it | `"use cache"`, or `await io()` + `<Suspense>`, or move to the client |
| Same calls during a **Client Component** render, including `useState(() => Date.now())` | Build error `blocking-prerender-current-time-client` [V] | Wrap in `<Suspense>` [V], move to an effect or handler [V], or `useSyncExternalStore` [V] |
| `usePathname` / `useParams` / `useSelectedLayoutSegment(s)` above a route whose params are not all from `generateStaticParams` | Build error `blocking-prerender-client-hook` [V] | `<Suspense>` around the smallest leaf that reads the hook |
| `useSearchParams` without `<Suspense>` | Build error, always [V] | `<Suspense>` |
| Uncached `fetch`, database call or async fs in render | Build error | `"use cache"` or `<Suspense>` |
| `generateStaticParams` returning `[]` | Build error [V] | Return at least one real param |
| `generateMetadata` reading runtime or uncached data on an otherwise static page | Error | `"use cache"` inside it, or a Suspense-wrapped `connection()` marker on the page |

Debug with `next dev` (source-mapped overlay) or `next build --debug-prerender --debug-build-paths="src/app/**/page.tsx"`. Never deploy a `--debug-prerender` build (guides/building.md).

**`"use cache"`** (api/directives/use-cache.md, api/fn/cacheLife.md, api/fn/cacheTag.md):

```ts
import { cacheLife, cacheTag } from 'next/cache'

export async function getNotices(airport: string) {
  'use cache' // function, component, or top of file; must be async
  cacheLife('hours') // always set one; the default profile is stale 5m / revalidate 15m / never expires
  cacheTag('notices', `notices-${airport}`)
  return loadNotices(airport)
}
```

- Arguments and closed-over values form the cache key; arguments and return values must be serializable (no class instances, functions, `URL`). Never call `cookies()` / `headers()` inside: read outside and pass values in.
- Passing a runtime Promise (params, cookies) into a cached function hangs the build for 50 s, then fails.
- Profiles: `seconds`, `minutes`, `hours`, `days`, `weeks`, `max`. `revalidate: 0` or `expire` under 5 minutes (the `seconds` profile) is **excluded from prerenders** and needs a `<Suspense>` boundary.
- A cached value captures time once: `new Date()` inside `"use cache"` is frozen until revalidation [V]. Invalidate with `revalidateTag('notices', 'max')` (route handlers) or `updateTag` (Server Functions). Entries do not survive a new deploy.
- Server-side time without caching: `await io()` (from `next/cache`) in a Suspense-wrapped component keeps what follows out of the shell. Prefer it to `connection()` (api/fn/io.md).

**`generateStaticParams`** (api/fn/generate-static-params.md, guides/incremental-static-regeneration-cache-components.md):

- Listed params are prerendered; with static or cached data each listed path is `○` [V]. The pattern row (e.g. `/[lang]/[airport]`) stays `◐`: it is the fallback shell for unlisted params.
- Unlisted params get the shell first, then are rendered and stored for later visitors [V]. A dynamic route **without** `generateStaticParams` renders on every request [V].
- A child segment's `generateStaticParams` receives the parent's params and returns only its own [V]. Build-time validation only covers code paths the listed params execute.

**Keeping a page fully static** (guides/keeping-pages-static.md, api/files/02-route-segment-config/ensureStatic.md): import content from modules, cache any async data, read no runtime APIs on the server, then enforce it with `export const ensureStatic = 'navigation'` (levels: `'shell'`, `'prefetch'`, `'navigation'`; the build fails if violated). `'navigation'` requires `generateStaticParams` on dynamic routes; an unlisted param then waits for the complete page, which also gives a real `404` on the first request [V].

## 3. Partial Prefetching (`partialPrefetching: true`)

- A default `<Link>` prefetches one reusable **App Shell per route** (output that does not depend on the link's URL), shared by every link to that route. `params`- and `searchParams`-dependent content resolves after the click (api/config/partialPrefetching.md, guides/adopting-partial-prefetching.md).
- `<Link prefetch={true}>` also resolves that link's URL data and the cached content behind it; this costs a server render per visible link unless the destination is fully static. Use it only where the content must be ready before the click.
- Requirements on our code: await `params` / `searchParams` **inside** `<Suspense>` so the shell is URL-independent (the dev-only `instant-shell-url-data` insight flags violations and never blocks the build [V]), and give every dynamic segment a meaningful fallback.
- `loading.tsx` is a plain Suspense boundary here, not a special prefetch marker. It wraps `page`, `not-found` and nested layouts, **not** the layout of its own segment (api/files/loading.md, api/files/layout.md).
- Cached content joins the App Shell only if its `stale` time is at least 5 minutes (api/fn/cacheLife.md).
- Prefetching runs only in production: judge navigation with `next build && next start` (api/components/link.md). `export const prefetch = 'force-disabled'` stops a segment being prefetched (api/files/02-route-segment-config/prefetch.md).

## 4. Server and Client Components

- Pages and layouts are Server Components. `'use client'` marks a boundary: that file and everything it imports ship to the browser, so put it on leaves (gs/05-server-and-client-components.md).
- Props crossing the boundary must be serializable. Server Components passed as `children` to a Client Component stay server-rendered. Use `import 'server-only'` in modules that must never reach the client.
- Context needs a Client Component provider taking `children`; render it inside `<body>`, as deep as possible. Feed it server-known values as props [V]:

```tsx
'use client'
import { createContext, useContext } from 'react'
const LocaleContext = createContext('en')
export function LocaleProvider({ lang, children }: { lang: string; children: React.ReactNode }) {
  return <LocaleContext.Provider value={lang}>{children}</LocaleContext.Provider>
}
export const useLang = () => useContext(LocaleContext)
```

- Prefer that over `useParams()` / `usePathname()` for the locale: URL hooks need `<Suspense>` on routes with unknown params (section 2), context does not [V].
- **Client Components are prerendered too.** Browser APIs do not exist during that render, and reading storage or the clock in render causes build errors or hydration mismatches. Safe options:
  1. `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` with a fixed server snapshot: builds without `<Suspense>` and passes lint [V]. Use it for storage-backed state and for "now".
  2. Read inside an event handler, or inside a subscription callback set up in `useEffect`.
  3. `use(browser())` from `react-dom` at the top of a component wrapped in `<Suspense>`: the fallback is the server HTML and the component renders only in the browser [V] (guides/single-page-applications.md).
- ESLint (`eslint-config-next`) rejects `Date.now()` during render (`react-hooks/purity`) and a synchronous `setState` in an effect (`react-hooks/set-state-in-effect`) [V]. A clock that passes both build and lint [V]:

```ts
// src/lib/time-store.ts
let now: number | null = null
const listeners = new Set<() => void>()
let timer: ReturnType<typeof setInterval> | undefined
const tick = () => { now = Date.now(); listeners.forEach((l) => l()) }
export function subscribeNow(l: () => void) {
  listeners.add(l)
  if (!timer) { tick(); timer = setInterval(tick, 30_000) }
  return () => { listeners.delete(l); if (!listeners.size && timer) { clearInterval(timer); timer = undefined } }
}
export const getNow = () => now // null until the first client tick
export const getServerNow = () => null // prerendered HTML shows the placeholder
// in a component: const now = useSyncExternalStore(subscribeNow, getNow, getServerNow)
```

- Anything rendered only on the client is absent from the static HTML [V]: crawlers and no-JS users see the placeholder. Keep indexable content server-rendered.
- **Theme without flash** (guides/preventing-flash-before-hydration.md): an inline script in `<head>` sets the attribute before first paint, and `suppressHydrationWarning` on `<html>` accepts the changed attribute.

```tsx
const themeScript = `(function(){try{var t=localStorage.getItem("theme");if(t)document.documentElement.setAttribute("data-theme",t)}catch(e){}})()`
// root layout:
<html lang={lang} data-theme="light" suppressHydrationWarning>
  <head><script dangerouslySetInnerHTML={{ __html: themeScript }} /></head>
```

- Do **not** read a theme cookie with `cookies()` in the root layout: that makes every route request-bound. Inline scripts need `'unsafe-inline'` (or a nonce) in the CSP (section 7).
- In dev, Strict Mode remounts and clears attributes the script set; re-apply them in a `useLayoutEffect` in the component that owns the toggle. State that mirrors the script uses a lazy initializer reading the same source. React warns about `<script>` rendered on the client; the docs' `InlineScript` helper (`type="text/javascript"` on the server, `"text/plain"` on the client) or `useServerInsertedHTML` avoids it.
- Preserved state: menus, popovers, dialogs and the command palette are still open when the user navigates back. Close transient UI in a `useLayoutEffect` cleanup or derive it from the URL (guides/preserving-ui-state.md).

## 5. Dynamic routes and static generation

Canonical dynamic page [V]:

```tsx
// src/app/[lang]/[airport]/page.tsx
import { Suspense } from 'react'
import { notFound } from 'next/navigation'

export function generateStaticParams() {
  return AIRPORT_CODES.map((airport) => ({ airport })) // [lang] values come from the root layout
}

export async function generateMetadata({ params }: PageProps<'/[lang]/[airport]'>) {
  const { airport } = await params
  return { title: getAirport(airport)?.name ?? 'Not found' }
}

export default function Page({ params }: PageProps<'/[lang]/[airport]'>) {
  return (
    <Suspense fallback={<AirportSkeleton />}>
      <AirportHome params={params} />
    </Suspense>
  )
}

async function AirportHome({ params }: Pick<PageProps<'/[lang]/[airport]'>, 'params'>) {
  const { airport } = await params
  const data = getAirport(airport)
  if (!data) notFound()
  return <h1>{data.name}</h1>
}
```

- Layouts must not `await params` at the top; pass the promise down to a Suspense-wrapped child (gs/08-caching.md). `dynamicParams = false` no longer exists; reject unknown values with `notFound()` (guides/migrating-to-cache-components.md).
- **Status codes** (api/files/loading.md, api/files/not-found.md): `notFound()` gives `404` only if it runs before the response starts. Measured for an unknown param on a route with `generateStaticParams` [V]: first request `200` with the not-found UI and `noindex`, later requests `404` from the stored result. With `ensureStatic = 'navigation'` the first request is already `404` [V]. For a guaranteed `404` use that, or check the slug in `proxy.ts`.
- Ids that cannot be enumerated (`[flightId]`): await `params` on the server inside `<Suspense>` and accept a render per request [V], or read the id with `useParams()` in a Suspense-wrapped Client Component so the server output stays a static shell (client hooks are allowed even under `ensureStatic`).
- `not-found.tsx` is sent with every route under its segment: keep it a light Server Component. Do not wrap `notFound()` in `try/catch`, and never leave it in an un-awaited promise (api/fn/not-found.md).
- With the root layout at `app/[lang]/layout.tsx` there is no `app/not-found.tsx` shell, so URLs matching no route get the bare built-in 404 [V]. `experimental: { globalNotFound: true }` plus `app/global-not-found.tsx` (a full document importing its own CSS and fonts) fixes that [V]. An invalid `[lang]` still matches the route: `notFound()` there returns `404` with Next's built-in error document [V], so reject unknown locales in `proxy.ts` if a branded page matters.
- `error.tsx` is a Client Component wrapping `loading`, `not-found`, `page` and nested layouts, not the layout of its own segment. `global-error.tsx` replaces the root layout and must render `<html>`, `<body>` and its own styles and theme (api/files/error.md).
- Hierarchy in a segment: `layout` > `template` > `error` > `loading` > `not-found` > `page`. Route groups `(name)` organise routes and layouts without changing the URL; `_folder` is never routable (gs/02-project-structure.md).
- Modal detail view (only if we want one): slot `@modal` with a `default.tsx` returning `null`, an intercepting `@modal/(.)flights/[flightId]/page.tsx` rendering `<Modal>` around the shared detail component, the slot rendered beside `children`, closed with `router.back()`. Direct loads render the full page. Costs: a catch-all slot page to close it on other navigations, and no static export (api/files/parallel-routes.md, api/files/intercepting-routes.md).

## 6. Route handlers

```ts
// src/app/api/flights/route.ts
import type { NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const airport = request.nextUrl.searchParams.get('airport') // reading the request makes it dynamic
  if (!airport) return Response.json({ error: 'airport is required' }, { status: 400 })
  return Response.json({ airport })
}
// dynamic segment: export async function GET(_req: NextRequest, ctx: RouteContext<'/api/flights/[id]'>) { const { id } = await ctx.params }
```

- `route.ts` cannot share a segment with `page.tsx`. Methods: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`; others return 405 (gs/15-route-handlers.md, api/files/route.md).
- Under Cache Components a `GET` handler follows the page model: it is **prerendered at build** when it touches no request data, uncached data or non-deterministic value (a constant `/api/health` is `○` and served from cache [V]); otherwise it runs per request (`ƒ`). Reading `request.url`, `request.headers`, `nextUrl.searchParams` [V], `headers()` or `Date.now()` [V] makes it dynamic. Other methods are never cached.
- `"use cache"` cannot go in the handler body: call a cached helper. The prerender bail-out is a thrown value, so a broad `try/catch` that logs adds build noise (guides/migrating-to-cache-components.md).
- Body: `await request.json()` / `request.formData()`. `notFound()` works in handlers and returns 404. No `runtime` export (build error [V]); handlers run on Node.js. `next/root-params` getters do not work in handlers, so send the locale in the request (api/fn/next-root-params.md).
- Streaming for the concierge [V]; behind nginx it needs `X-Accel-Buffering: no` (guides/self-hosting.md):

```ts
export async function POST(request: Request) {
  const { question } = (await request.json()) as { question: string }
  const encoder = new TextEncoder()
  const stream = new ReadableStream({
    async start(controller) {
      for await (const chunk of answer(question)) controller.enqueue(encoder.encode(chunk))
      controller.close()
    },
  })
  return new Response(stream, { headers: { 'Content-Type': 'text/plain; charset=utf-8' } })
}
```

## 7. `proxy.ts`, security headers and CSP

- One file, `src/proxy.ts` (same level as `app`), exporting `proxy(request: NextRequest)` and an optional `config.matcher`. It can redirect, rewrite, set request or response headers and cookies, or respond directly. Without a matcher it runs on **every** request, including `_next/static` and `public/` files; matcher values must be constants. `"use cache"` and `fetch` cache options do nothing in it (gs/16-proxy.md, api/files/proxy.md).
- Order: `headers` from `next.config`, then `redirects`, then Proxy, then filesystem routes. To pass data to rendering use `NextResponse.next({ request: { headers } })`, not `NextResponse.next({ headers })`.
- Locale redirect for the bare `/` [V]:

```ts
import { NextResponse, type NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const cookie = request.cookies.get('lang')?.value
  const accept = request.headers.get('accept-language') ?? ''
  const lang = cookie === 'en' || cookie === 'ms' ? cookie : /^ms\b/i.test(accept) ? 'ms' : 'en'
  return NextResponse.redirect(new URL(`/${lang}`, request.url))
}
export const config = { matcher: '/' }
```

- **CSP: static headers, not nonces.** A nonce needs every page rendered per request and is incompatible with Partial Prerendering (guides/content-security-policy.md). Measured [V]: with a nonce CSP set in `proxy.ts`, a prerendered page shipped 17 `<script>` tags and none carried the nonce, so a browser would block them all. Prerendered HTML also contains framework inline `<script>` tags [V], so without nonces `script-src` needs `'unsafe-inline'`. The docs' static variant:

```ts
// next.config.ts
const isDev = process.env.NODE_ENV === 'development'
const csp = [
  "default-src 'self'",
  `script-src 'self' 'unsafe-inline'${isDev ? " 'unsafe-eval'" : ''}`, // React needs eval in dev only
  "style-src 'self' 'unsafe-inline'",
  "img-src 'self' blob: data:",
  "font-src 'self'",
  "object-src 'none'", "base-uri 'self'", "form-action 'self'", "frame-ancestors 'none'",
].join('; ')

const nextConfig: NextConfig = {
  // ...existing options
  async headers() {
    return [{ source: '/(.*)', headers: [
      { key: 'Content-Security-Policy', value: csp },
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'X-Frame-Options', value: 'DENY' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
    ] }]
  },
}
```

- The docs' sample also sends `upgrade-insecure-requests`; add it only where the site is served over HTTPS. Trade-off: static headers keep every page static and CDN-cacheable but allow inline scripts. The only stricter option without nonces is experimental SRI (`experimental.sri`), which hashes script files at build time; treat it as unproven.

## 8. Metadata

- Static: `export const metadata: Metadata`. Dynamic: `export async function generateMetadata({ params })`. Server Components only. Segments merge shallowly from root to page, so nested objects such as `openGraph` are replaced, not merged (gs/14-metadata-and-og-images.md, api/fn/generate-metadata.md).
- Set `metadataBase` once in the root layout (relative URLs without it are a build error) and use `title: { default, template: '%s | Site' }`. Do not hand-write `<title>` or `<meta>` in the root layout.
- Under Cache Components `generateMetadata` follows the component rules. Reading `params` supplied by `generateStaticParams` is fine [V]. For external data add `"use cache"` and return strings, not `URL` objects. Prerendered pages resolve metadata at build time; streaming metadata applies to request-time pages only.
- `themeColor` and `colorScheme` belong in `export const viewport: Viewport`. Keep it static: a request-dependent `generateViewport` blocks the whole document (api/fn/generate-viewport.md).
- Files in `app/` (api/files/01-metadata/): `favicon.ico` (root only), `icon.(png|svg)`, `apple-icon.png`, `opengraph-image.(png|jpg)` or `opengraph-image.tsx` using `ImageResponse` from `next/og` (flexbox only, `params` is a Promise), `sitemap.ts`, `robots.ts`, `manifest.ts`. `manifest.ts` adds `<link rel="manifest">` automatically [V]. All three were prerendered (`○`) [V]. Prefer fixed `lastModified` dates: a non-deterministic value makes a plain GET handler dynamic [V]; not checked for `sitemap.ts`.
- JSON-LD (guides/json-ld.md): a native `<script>` in the page with `<` escaped:

```tsx
<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }} />
```

## 9. Fonts

```ts
// src/app/fonts.ts (one definitions file: every localFont() call is a separately hosted instance)
import localFont from 'next/font/local'

export const brand = localFont({
  src: '../fonts/Brand-Variable.woff2', // relative to THIS file
  weight: '100 900', // range for a variable font; static fonts need a single weight
  display: 'swap',
  variable: '--font-brand',
})
// root layout: <html lang={lang} className={`${brand.variable} ${mono.variable}`}>
// globals.css: @theme inline { --font-sans: var(--font-brand); }  -> .font-sans { font-family: var(--font-brand) } [V]
```

- `next/font/local` self-hosts the file, emits `@font-face` plus a metric-adjusted fallback face (default `adjustFontFallback: 'Arial'`) and a preload header [V] (gs/13-fonts.md, api/components/font.md).
- Several static files: `src: [{ path, weight, style }, ...]`. Preload scope follows where the font object is used: root layout means every route. Do not use `next/font/google` (the scaffold does): it downloads font files at build time. `@fontsource` CSS imports work as ordinary stylesheets but give no fallback metrics or preloading (not covered by the docs), so prefer `next/font/local`.

## 10. CSS and Tailwind v4

- Tailwind is wired as a Turbopack loader in `next.config.ts`, not through PostCSS (the Next.js docs show the PostCSS route; do not add both). The rule only applies under Turbopack, so never build with `--webpack` (api/config/turbopack.md, `node_modules/@tailwindcss/turbopack/README.md`):

```ts
turbopack: { rules: { '*.css': { loaders: ['@tailwindcss/turbopack'], as: '*.css' } } }
```

- The directives below are Tailwind features, not covered by the Next.js docs; each compiled correctly through this loader [V]:

```css
@import "tailwindcss";

/* dark: variant driven by <html data-theme="dark"> instead of prefers-color-scheme */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

:root { --background: #ffffff; --foreground: #171717; }
[data-theme="dark"] { --background: #0a0a0a; --foreground: #ededed; }

@theme { --color-brand-500: oklch(0.6 0.2 250); } /* emits a :root variable plus text-brand-500 etc. */
@theme inline { /* utilities reference the variable instead of copying its value */
  --color-background: var(--background);
  --font-sans: var(--font-brand);
}
@utility focus-ring { outline: 2px solid var(--color-brand-500); outline-offset: 2px; }
```

- Use `@theme inline` whenever a token points at a variable that changes at runtime (theme switch, `next/font` variable on `<html>`).
- Global CSS may be imported from any layout, page or component in `app/`, but stylesheets are **not removed on navigation**: import `globals.css` once in the root layout (and again in `global-not-found.tsx`). CSS order follows import order and can differ between dev and build, so check with `next build` (gs/11-css.md). A page-level `<style>` in a hidden (preserved) route still applies; toggle its `media` while hidden (guides/preserving-ui-state.md).

## 11. Images

- Static import (`import hero from './hero.png'`): width, height and blur placeholder are inferred. A string path into `public/` needs `width` and `height`, or `fill` with a positioned parent plus `sizes` (gs/12-images.md, api/components/image.md).
- SVG is never optimized: `next/image` applies `unoptimized` automatically when `src` ends in `.svg`, so nothing needs configuring and `dangerouslyAllowSVG` stays off. Otherwise `unoptimized` is only worth it for images under 1 KB and animated GIFs.
- `preload` replaces `priority`; for the LCP image the docs usually prefer `loading="eager"` or `fetchPriority="high"`. Without `sizes` a responsive image is assumed to be `100vw`. `quality` values outside `images.qualities` are coerced to the nearest allowed one.
- Remote images need `images.remotePatterns` (protocol, hostname, pathname). We serve none, so leave it unset. Optimization runs on the server at request time (`next start`); a static export would need a custom loader.

## 12. Internationalisation

- **What the docs recommend** (guides/internationalization.md): a locale segment `app/[lang]/…`, a Proxy redirect choosing the locale from `Accept-Language`, per-locale dictionaries loaded in Server Components (so they stay out of the client bundle) and `generateStaticParams` listing the locales. `build-spec.md` follows this. Verified shape [V]:

```tsx
// src/app/[lang]/layout.tsx (root layout; lang is a "root param")
import { lang } from 'next/root-params'

export function generateStaticParams() {
  return [{ lang: 'en' }, { lang: 'ms' }] // required under Cache Components
}

export default async function RootLayout({ children }: LayoutProps<'/[lang]'>) {
  const language = await lang()
  return (
    <html lang={language} data-theme="light" suppressHydrationWarning>
      <body><LocaleProvider lang={language}>{children}</LocaleProvider></body>
    </html>
  )
}
```

- Result [V]: `/en` and `/ms` are both `○` with the right `<html lang>`, and `/` redirects through `proxy.ts`.
- `next/root-params` getters (`await lang()`) work in any Server Component and inside `"use cache"` (they join the cache key), but not in Client Components, Server Actions or route handlers. Reading one at the top of a layout or page raised no dev insight [V] (api/fn/next-root-params.md).
- `params.lang` is typed `string`: narrow it with a type guard (api/files/dynamic-routes.md). Client Components get strings through props or the context provider; send only the keys the client needs.
- **Without a locale prefix** (cookie or `localStorage` plus client dictionaries), the simplest form is static HTML in the default language, both dictionaries in the client bundle, the locale read through `useSyncExternalStore` with the default as server snapshot, and an inline script setting `<html lang>` before paint. Implications: pages stay fully static, but non-default users see default-language text until hydration, crawlers index one language, there are no per-language URLs or `hreflang`, and all translated UI must be Client Components. Reading the cookie on the server instead makes that subtree request-time behind `<Suspense>`; reading it in the root layout makes the whole app request-bound (guides/preventing-flash-before-hydration.md).

## 13. PWA and offline

- `src/app/manifest.ts` returns `MetadataRoute.Manifest` (name, short_name, start_url, display, background_color, theme_color, icons from `public/`). Installability needs the manifest and HTTPS (guides/progressive-web-apps.md).
- Service worker, two options (serving verified [V]; registration in a real browser not exercised): (a) `public/sw.js` registered from a Client Component effect with `navigator.serviceWorker.register('/sw.js', { scope: '/', updateViaCache: 'none' })`; (b) the docs' form `register(new URL('../lib/service-worker.js', import.meta.url), { scope: '/' })`, which Next.js bundles and serves at `/_next/static/service-worker/sw.js` with `Service-Worker-Allowed: /`.
- Give the worker its own headers in `next.config`: `Content-Type: application/javascript; charset=utf-8`, `Cache-Control: no-cache, no-store, must-revalidate`, `Content-Security-Policy: default-src 'self'; script-src 'self'`. Files in `public/` are otherwise served with `Cache-Control: public, max-age=0` [V].
- Caveat (our inference from observed headers, not in the docs): a page URL returns HTML or an RSC payload depending on request headers, and responses carry `Vary: rsc, next-router-state-tree, next-router-prefetch, next-router-segment-prefetch` [V]. A worker that caches by URL alone can serve the wrong one: cache document navigations (`request.mode === 'navigate'`) separately and let RSC requests go to the network. Test with `next build && next start`.
- `experimental.useOffline` (guides/offline-support.md) keeps failed soft navigations, prefetches and Server Actions pending and retries on reconnect, and exposes `useOffline()` from `next/offline` for a banner. It only covers client navigations into already-prefetched routes; a full reload offline still needs the service worker. The docs name Serwist for full service-worker caching.

## 14. View transitions and instant navigation

- No config needed: `import { ViewTransition } from 'react'`. Navigations are transitions, so they animate automatically; unsupported browsers simply do not animate (guides/view-transitions.md).
- Shared element: the same `<ViewTransition name="outlet-123">` around the thumbnail and the detail hero. The morph plays only if the destination renders in the same commit (prefetched); if it suspends first, the enter animation plays instead. Add `share="morph" default="none"` so named elements do not animate on every transition.
- Direction: `<Link transitionTypes={['nav-forward']}>` (also an option of `router.push`), mapped by `enter` / `exit` props on a `<ViewTransition>` placed in each `page.tsx`, **not** in layouts (layouts persist, so they never enter or exit).
- Always ship: `::view-transition { pointer-events: none }`, a header pinned with `viewTransitionName` and its animation disabled, and a `prefers-reduced-motion` rule zeroing `::view-transition-*` durations (repeat it for our own reduced-motion preference).
- Instant navigation (guides/instant-navigation.md): a navigation is instant when static, cached and fallback UI render at the click. Dev validates every page; findings appear in the overlay and the dev server log, never in the HTTP response. A `<Suspense>` in the root layout covers a page load but not a client navigation between sibling pages, so put boundaries inside pages. `export const instant = false` accepts blocking for one segment (api/files/02-route-segment-config/instant.md). Inspect what a navigation shows first with Next.js DevTools > Navigation Inspector > "Pause on navigations".

## 15. Linking and navigation

- `<Link>` prefetches when it enters the viewport (production only); `prefetch={false}` disables it, `prefetch={true}` adds per-link URL data (section 3). A plain `<a>` does a full page load (gs/04-linking-and-navigating.md, api/components/link.md).
- `useRouter` from `next/navigation`: `push` and `replace` (both take `{ scroll, transitionTypes }`), `refresh`, `prefetch`, `back`, `forward`. Never pass unsanitised URLs to `push` (api/fn/use-router.md).
- `usePathname`, `useParams`, `useSelectedLayoutSegment(s)` resolve at build when every param comes from `generateStaticParams`; otherwise they suspend, and a missing boundary fails the build [V]. Our header sits above `/[lang]/[airport]/flights/[flightId]`, so wrap **only the leaf that reads the hook** in `<Suspense>` with a fallback rendering the same links without the active state: on those routes the shell shows the fallback until the stream arrives [V] (api/fn/use-pathname.md).
- `useSearchParams` always needs `<Suspense>` [V]. In event handlers read `window.location.search` instead. Layouts never receive `searchParams` (api/fn/use-search-params.md). URL-only state (filters, `?t=T1`): `window.history.pushState` / `replaceState` are integrated with the router and update the hooks without a server round trip.
- Scroll: Next.js scrolls to the new page only if it is not already visible, skipping sticky and fixed elements; set `html { scroll-padding-top: <header height> }`. `scroll={false}` opts out.
- Accessibility: the built-in route announcer reads `document.title`, then the `<h1>`, then the pathname, so every page needs a unique title and one `<h1>` (`../03-architecture/accessibility.md`). Focus stays where it was after a client navigation; moving it to the main heading is our job.

## 16. Testing and commands

- **Vitest** (guides/testing/vitest.md): install `vitest @vitejs/plugin-react jsdom @testing-library/react @testing-library/dom vite-tsconfig-paths`. Async Server Components are not supported: unit-test pure logic, hooks and synchronous components, and cover async pages end to end. Vitest watches by default; use `vitest run` in CI.

```ts
import react from '@vitejs/plugin-react'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({ plugins: [tsconfigPaths(), react()], test: { environment: 'jsdom' } })
```

- **Playwright** (guides/testing/playwright.md): test production code: `npm run build && npm run start`, then `npx playwright test` (or let `webServer` start it). Set `baseURL` and use `page.goto('/en')`.
- Hidden preserved routes stay in the DOM with `display: none`. Use `getByRole` (ignores hidden elements) or `.filter({ visible: true })`; bare `locator()`, `getByLabel` and `getByPlaceholder` can match a hidden copy and trip strict mode (guides/preserving-ui-state.md).
- `@next/playwright` exports `instant(page, fn, { baseURL })` to assert what is visible before streamed content arrives. It works against `next dev`; a production build needs `experimental.exposeTestingApiInProductionBuild` set at build time, for the test build only (guides/instant-navigation.md).
- Dev differs from production for prefetching, offline behaviour and status codes (an unknown airport returned `404` at once in dev but `200` first in production [V]): assert those against a production build.

## 17. Production checklist and deployment constraints

Highlights (guides/production-checklist.md, guides/self-hosting.md):

- Keep `'use client'` on leaves and lazy-load heavy client-only widgets. Wrap request-time work in `<Suspense>`. Fonts through `next/font`, images through `next/image`. Add `global-error.tsx`, `not-found.tsx`, `global-not-found.tsx`, sitemap, robots, OG images and a CSP.
- Do not call our own route handlers from Server Components: import the function instead. Only `NEXT_PUBLIC_` variables reach the client. Measure with Lighthouse against `next build && next start`.
- Self-hosting: `next start` supports every feature. Streaming needs unbuffered proxies end to end. `"use cache"` entries live in memory per instance; several instances need a shared cache handler for tag invalidation.

**`output: 'export'` is not an option for this project** (guides/static-exports.md, api/directives/use-cache.md, api/files/loading.md, api/files/proxy.md):

| Planned feature | Why it breaks in a static export |
|---|---|
| `proxy.ts` (locale redirect for `/`) | Proxy is unsupported |
| Security headers and CSP from `next.config` `headers()` | Headers, redirects and rewrites are unsupported |
| `/api/flights`, `/api/concierge`, `/api/search` | Only static `GET` handlers are supported; nothing that reads the request, no POST |
| Streamed concierge answers, `loading.tsx` streaming | Needs a server |
| `/[lang]/[airport]/flights/[flightId]` with unknown ids | Dynamic routes need every path in `generateStaticParams`; no ISR |
| `"use cache"` | Not supported on static export |
| `next/image` optimization | Default loader is unsupported |
| Intercepting routes (modal detail) | Unsupported |

Fine in an export: fully enumerated static pages, Client Components, static manifest/robots/sitemap, a service worker in `public/`. Deploy with `next start` (optionally `output: 'standalone'` in Docker).

## 18. Do / Don't

1. **Do** await `params` and `searchParams` inside a `<Suspense>` child; **don't** await them at the top of a page or layout.
2. **Do** give every enumerable dynamic segment a `generateStaticParams` returning at least one real value; **don't** return `[]`.
3. **Don't** export `dynamic`, `dynamicParams`, `revalidate`, `fetchCache` or `runtime`: each fails the build.
4. **Don't** call `new Date()`, `Date.now()`, `Math.random()` or `crypto.randomUUID()` during any render, server or client.
5. **Do** read the clock and `localStorage` through `useSyncExternalStore` with a fixed server snapshot, or in handlers and subscriptions.
6. **Do** wrap every `useSearchParams` consumer, and every `usePathname` / `useParams` consumer in shared chrome, in `<Suspense>` at the smallest leaf.
7. **Do** pass the locale to Client Components through context from the root layout; **don't** derive it from URL hooks.
8. **Don't** call `cookies()` or `headers()` in the root layout, in `generateViewport`, or inside `"use cache"`.
9. **Do** pair every `"use cache"` with `cacheLife(...)` and `cacheTag(...)`, and keep its arguments serializable.
10. **Do** use `notFound()` for unknown params, knowing the first response may be `200`; use `ensureStatic = 'navigation'` or a Proxy check where a real `404` matters.
11. **Do** set the theme and other `<html>` attributes with the inline head script plus `suppressHydrationWarning`; **don't** fix them up in `useEffect`.
12. **Do** ship the CSP as static headers in `next.config.ts`; **don't** use nonces.
13. **Do** name the request interceptor `src/proxy.ts` and give it an explicit `matcher`; **don't** create `middleware.ts`.
14. **Do** type props with `PageProps` / `LayoutProps` / `RouteContext`, and run `next typegen` before `tsc`.
15. **Do** load fonts with `next/font/local` from one `fonts.ts`; **don't** use `next/font/google` or font CDNs.
16. **Do** import `globals.css` only in the root layout and keep tokens in `@theme` / `@theme inline`.
17. **Do** use `<Link>` for internal navigation, with `prefetch={true}` only where URL-specific content must be ready before the click.
18. **Do** close transient UI (menus, dialogs, command palette) when its route is hidden: state now survives navigation.
19. **Do** test navigation, prefetching, offline and status codes against `next build && next start`, with `getByRole` locators.
20. **Don't** plan for `output: 'export'`, and run `eslint` yourself: `next build` no longer lints.
